# KaiSpan 人事 Demo · 程序员交接

交接日期：2026-10-30。此包是交互原型与业务流程参考，不是生产系统。

## 启动

安装 Node.js 22.12+（或 20.19+），在解压目录执行：

```sh
pnpm install
pnpm dev
```

打开 http://127.0.0.1:5174/ 。端口固定；被占用时先关闭占用该端口的服务。不要直接双击 index.html。首次安装开发依赖需要联网，之后页面与 PDF 渲染使用本地资源。

```sh
pnpm check
pnpm test
```

这是原生 JavaScript/CSS 静态原型，不包含 React 构建、TypeScript、后端、src/lib/api.ts 或生产数据库。包中只保留实际启动需要的 Vite，固定为已验证的 8.2.2。无编译构建步骤。

## 演示入口

- `#todos`：人事待办，切换员工端与老板端；统一列出档案提醒与流程示例，小叹号内是完整纳入规则。
- `#employee`：完整版员工助手；包含员工档案、排班与考勤、工时、工资与发薪。
- `#employee-ui`：员工端演示，邀请 → 设置密码 → 材料 → 工作台；“重新体验注册”重新走流程，不清除已存资料。材料页可“测试跳过，进入工作台”，不会伪造提交或审批结果。
- `#hr-lite`：简易版，手工录入月度薪资数据，与税务师协作。
- 新增员工可由公司代填上传，或生成邀请让员工补充；资料齐全的邀请进入账号激活演示。
- 完整版与简易版共用员工档案。员工端按邀请对应本人，字段、文件与有效期双向同步。

## 核心业务约定

1. 个人资料与证件分开；合同摘要保留工时、固定月薪或时薪、年假、通知期及其他约定，以签署原文为准。
2. 学生需在读证明；非 EU 需签证/居留许可，持有 Zusatzblatt 时上传。身份证明、银行卡正反面、签署合同、问卷等按界面条件校验。
3. 税号、社保号、医保及卫生证明暂缺走特殊审批；其他适用必填项仍需补齐。界面为用户设定的流程，不表示法律上可免交。
4. 月度工时确认由员工回复确认，雇主不可替员工确认；有异议进入沟通与核对。
5. 工时日历同时展示排班、打卡、计薪及年假/病假，可在提交前修正；原始打卡记录保留。早到按排班开始，迟到向后取整至 15 分钟，其他规则见代码。
6. Arbeitszeitkonto 存取联动本月工时，推荐方向只作提示；提交前由雇主决定。已封账资料走独立更正，保留原快照。
7. 演示以 2026 年 10 月为未提交月份，9 月为已提交案例。工资单由税务师回传；Netto 取工资单，不由雇主手填。PDF 匹配需比较预期 Brutto 与回传值。
8. 批量发送工资单、SEPA XML 生成、付款状态均为演示；下载 XML 不等于银行已打款。
9. 有效期、截止日期、委派、完成待验收、退回补充、审批与异常都纳入待办。流程示例文字明确标识，不表示真实事件已发生。

## 数据、文件与生产化边界

- 演示数据由源码种子及当前浏览器 localStorage/文件存储组成。交接包不读取或携带原浏览器中的私人材料、手动填写值或账号信息；换电脑/浏览器/端口看到的可能是种子数据。
- 这不是本地数据备份包。原浏览器数据未重置、未清除；如需迁移真实资料，应另行设计明确授权的安全导入导出。
- 邮件、特殊审批通知、发送工资单及密码激活均为模拟；密码未保存为真实认证凭证；演示设置页不强制填写、长度或两次一致，可直接继续。生产版需补齐身份认证、权限隔离、文件存储、邮件接收发送、审计及税务师接口。
- 上传文件目前有限制，旧文件/更正记录保留。生产版应改由统一 API 服务管理数据和文件，而非直接复用浏览器存储。
- 现有示例内可能保留早期时薪、Minijob 阈值、日期及税务示例；不得作为现行德国合规结论。正式实施须由税务师/专业人员确认当年参数、差旅、计薪及申报口径。
- 两端切换是原型预览，不是实际权限隔离。PDF 示例及 Netto 示例不是正式工资结算结果。

## 建议验收顺序

1. 新增员工两种路径、条件材料、文件与档案同步。
2. 密码步骤、资料提交与特殊审批，员工/老板对应关系。
3. 排班、打卡、工时日历、年假/病假与工时账户。
4. 员工确认/异议、提交税务师、封账快照与后续更正。
5. 工资单回传、PDF 对比、工资单发送与 XML 导出。
6. 任务委派、提交、验收/退回及双向待办。

## 材料有效期统一规则（2026-10-30 更新）

- 护照/身份证、签证/居留许可、适用的 Zusatzblatt、在读证明：按材料填写完整有效期年月日。
- 健康证/食品卫生指导证明：必须填写截止日期；到期同时提醒员工与老板安排继续培训，完成后更新证明与日期。
- 医保卡与银行卡正反面：不要求截止日期；已有历史日期保留，不再用于到期提醒。
- 劳动合同的期限在合同摘要/合同关键条款中维护；个人问卷不默认增加有效期。
- 员工端上传/更新与公司代填使用相同日期字段；完整版和简易版共用员工档案，日期双向同步。
- 有期限的材料已上传却缺有效期时，显示“有效期待补充”，进入提醒；过期与即将到期仍按档案规则提醒。
- 替换文件保留上一版记录，新材料重新核对日期。演示跳过保留，不代表资料已正式提交。
- 回归检查包含 `tests/document-expiry.cjs`，覆盖完整日期、非法日期、缺日期状态、无明确截止日期与旧档案双向同步。

## 劳动合同的后置流程

员工先填写个人资料、上传身份证明等材料和个人调查问卷；首次提交不要求劳动合同。提交后等待店长审核，审核通过后公司在员工档案的证件页上传并明确发送待签合同，员工才可在后续合同步骤下载、签署并上传。待签原件与员工签署版本分开保留，发送为本机演示。演示跳过不等于资料审批通过。

合同相关待办按阶段自动汇总：员工提交后提醒老板审核；审核通过后提醒制作上传合同；发送后提醒员工签署上传；签回后提醒老板核对归档；确认归档后办结。待办页保留四类明确标识的流程示例。本机演示记录状态，不发送真实邮件。
