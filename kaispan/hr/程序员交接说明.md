# KaiSpan 人事 Demo · 程序员交接

交接日期：2026-10-30；2026-11-06 按 KaiSpan 员工助手一期规则（`261105-employee-assistant-phase1` 的 rules/01–09）对齐，对齐内容见文末“一期规则对齐”。此包是交互原型与业务流程参考，不是生产系统。

## 启动

安装 Node.js 22.12+（或 20.19+），在解压目录执行：

```sh
pnpm install
pnpm dev
```

打开 http://127.0.0.1:5174/ 。端口固定；被占用时先关闭占用该端口的服务。不要直接双击 index.html。首次安装开发依赖需要联网，之后页面与 PDF 渲染使用本地资源。

```sh
pnpm check
pnpm test
```

这是原生 JavaScript/CSS 静态原型，不包含 React 构建、TypeScript、后端、src/lib/api.ts 或生产数据库。包中只保留实际启动需要的 Vite，固定为已验证的 8.2.2。无编译构建步骤。

## 演示入口

- 顶栏“视角”：老板 / 店长切换（店长下有“店长权限”演示开关：是否被老板开通发邀请、是否可查看敏感资料）。规则里一批界面差异取决于视角，演示时先选好视角。
- `#todos`：人事待办的**事项类型清单**（HR-TODO-20～39 逐类写明何时开、何时关、给谁），加“人事”分行示意和按当前演示档案生成的几条实例；排班、考勤、薪资、HACCP 灰显为二、三期。真实待办页是 KaiSpan 现有待办页加一行“人事”。
- `#employee`：完整版员工助手；包含员工档案、排班与考勤、工时、工资与发薪。
- `#employee-ui`：员工端演示，邀请 → 设置密码（至少 6 位）→ 入职资料（三层必填）→ 提交锁定 / 退回 / 撤回 → 合同与问卷两份签回 → 工作台；页头“演示状态”下拉可一键切到被退回、公司代填、老员工开通、待确认关联等画面（演示用，正式版没有）。一期语言范围是中文、德文、英文，原型另保留越、韩、日。“今日 / 排班 / 薪资”页签一期显示“即将开放”。
- `#employee-税务师权限`：老板按雇主打开 / 关闭“税务师可读 HR 资料”（默认关闭，记录打开人和时间）；入口在员工助手首页右上角。一期没有税务端页面，只画老板这一侧。
- `#hr-lite`：简易版，手工录入月度薪资数据，与税务师协作。
- 新增员工可由公司代填上传，或生成邀请让员工补充；资料齐全的邀请进入账号激活演示。
- 完整版与简易版共用员工档案。员工端按邀请对应本人，字段、文件与有效期双向同步。

## 核心业务约定

1. 个人资料与证件分开；合同摘要保留工时、固定月薪或时薪、年假、通知期及其他约定，以签署原文为准。
2. 国籍是三个值：未回答 / 欧盟、欧洲经济区或瑞士公民 / 其他国籍；未回答时材料清单显示“待确认国籍”。学生由员工自答，合同类型选 Werkstudent 也视为学生，需在读证明；其他国籍需居留许可（含临时替代证明），Zusatzblatt 由店长核对居留证件后勾选，员工本人不选。
3. 只有税号、社保号、医保公司、医保卡号、医保卡照片、健康证首次证明六项可申请暂缺；批准时必填最晚补交日（默认取批准日 + 30 天与入职日 + 60 天中较早的），同一项最多延期 1 次，从入职算最长 60 天。界面为用户设定的流程，不表示法律上可免交。
4. 月度工时确认由员工回复确认，雇主不可替员工确认；有异议进入沟通与核对。
5. 工时日历同时展示排班、打卡、计薪及年假/病假，可在提交前修正；原始打卡记录保留。早到按排班开始，迟到向后取整至 15 分钟，其他规则见代码。
6. Arbeitszeitkonto 存取联动本月工时，推荐方向只作提示；提交前由雇主决定。已封账资料走独立更正，保留原快照。
7. 演示以 2026 年 10 月为未提交月份，9 月为已提交案例。工资单由税务师回传；Netto 取工资单，不由雇主手填。PDF 匹配需比较预期 Brutto 与回传值。
8. 批量发送工资单、SEPA XML 生成、付款状态均为演示；下载 XML 不等于银行已打款。
9. 有效期、截止日期、委派、完成待验收、退回补充、审批与异常都纳入待办。流程示例文字明确标识，不表示真实事件已发生。

## 数据、文件与生产化边界

- 演示数据由源码种子及当前浏览器 localStorage/文件存储组成。交接包不读取或携带原浏览器中的私人材料、手动填写值或账号信息；换电脑/浏览器/端口看到的可能是种子数据。
- 这不是本地数据备份包。原浏览器数据未重置、未清除；如需迁移真实资料，应另行设计明确授权的安全导入导出。
- 邮件、特殊审批通知、发送工资单及密码激活均为模拟；密码未保存为真实认证凭证；演示设置页不强制填写、长度或两次一致，可直接继续。生产版需补齐身份认证、权限隔离、文件存储、邮件接收发送、审计及税务师接口。
- 上传文件目前有限制，旧文件/更正记录保留。生产版应改由统一 API 服务管理数据和文件，而非直接复用浏览器存储。
- 现有示例内可能保留早期时薪、Minijob 阈值、日期及税务示例；不得作为现行德国合规结论。正式实施须由税务师/专业人员确认当年参数、差旅、计薪及申报口径。
- 两端切换是原型预览，不是实际权限隔离。PDF 示例及 Netto 示例不是正式工资结算结果。

## 材料有效期统一规则（2026-10-30 更新；2026-11-06 起以文末“一期规则对齐”为准）

> 2026-11-06 变化：材料叫法统一为“护照 / 身份证”“居留许可（含临时替代证明）”；居留许可可勾“无截止日期”；健康证改记“首次指导证明（有 / 无）+ 最近一次复训日”，下次复训日 = 最近复训日 + 2 年，只对下次复训日提醒；替换文件时新版本有效期初始为空，必须填新日期或写明“保留原日期”的原因，旧版本标“已被替换”并可在“历史版本”查看；上传限制为 PDF、PNG、JPEG，最大 20 MB，银行卡、医保卡只收照片。以下为 10-30 的原文，其中与上述冲突的部分已作废。

- 护照/身份证、签证/居留许可、适用的 Zusatzblatt、在读证明：按材料填写完整有效期年月日。
- 健康证/食品卫生指导证明：必须填写截止日期；到期同时提醒员工与老板安排继续培训，完成后更新证明与日期。
- 医保卡与银行卡正反面：不要求截止日期；已有历史日期保留，不再用于到期提醒。
- 劳动合同的期限在合同摘要/合同关键条款中维护；个人问卷不默认增加有效期。
- 员工端上传/更新与公司代填使用相同日期字段；完整版和简易版共用员工档案，日期双向同步。
- 有期限的材料已上传却缺有效期时，显示“有效期待补充”，进入提醒；过期与即将到期仍按档案规则提醒。
- 替换文件保留上一版记录，新材料重新核对日期。演示跳过保留，不代表资料已正式提交。
- 回归检查包含 `tests/document-expiry.cjs`，覆盖完整日期、非法日期、缺日期状态、无明确截止日期与旧档案双向同步。

## 劳动合同的后置流程（2026-11-06：合同与问卷两份一起走，见文末）

员工先填写个人资料、上传身份证明等材料和个人调查问卷；首次提交不要求劳动合同。提交后等待店长审核，审核通过后公司在员工档案的证件页上传并明确发送待签合同，员工才可在后续合同步骤下载、签署并上传。待签原件与员工签署版本分开保留，发送为本机演示。演示跳过不等于资料审批通过。

合同相关待办按阶段自动汇总：员工提交后提醒老板审核；审核通过后提醒制作上传合同；发送后提醒员工签署上传；签回后提醒老板核对归档；确认归档后办结。待办页保留四类明确标识的流程示例。本机演示记录状态，不发送真实邮件。

## 一期规则对齐（2026-11-06）

### 来源与范围

- 规则：KaiSpan PR #390 `261105-employee-assistant-phase1`（提交 `da260b85e`）的 `rules/01–09`；对照清单：`员工助手-原型vs规则-差异清单.md`（不在本仓库，由 Owner 保管）。规则与原型冲突时以规则为准；规则没写的保持原型现状。
- 只涉及一期页面。排班、考勤、休假、工资（二、三期）、HACCP、简易版 `#hr-lite`、旧员工入口 `#me` 没动。
- 仍保持纯原生 JS/CSS，无后端、无 React；所有数据在浏览器 localStorage，文件以 dataUrl 存放，邮件与通知都是模拟。

### 视角与权限（`viewpoint.js`）

- `hrView()` 为 `owner` 或 `manager`；`hrCan('invite' | 'sensitive' | 'ownerOnly' | 'confirmProposal')` 给出能力，`hrDenyReason()` 给出置灰原因。权限判断同时放在按钮和函数入口里，直接调用函数也会被拒。
- 店长：默认不能发邀请；改薪资、合同条件、办离职只形成“等待老板确认”的提案；可被老板关闭“查看敏感资料”（关闭后审核入职、核对归档、批准暂缺、下载文件、导出敏感列被拒）。试用期结束日、调店、改证件提醒天数、关联已有账号、合规设置、税务师权限只有老板和管理员。
- 演示开关存 localStorage：`kaispanHrView`、`kaispanHrMgrPerm`。

### 共用资料约定（`hr-model.js`，老板端与员工端共享同一份员工档案）

| 约定 | 字段 / 函数 |
|---|---|
| 国籍类别 | `contract.nationalityClass`：`''` / `eu` / `other`；`hrNationalityClass()`；旧 `nonEU` 同步派生 |
| 学生 | `contract.isStudent`：`null` 未回答 / `true` / `false`；`hrIsStudent()`（Werkstudent 也算学生） |
| Zusatzblatt | `contract.zusatzCheck`：`''` 未核对 / `no` / `yes`；`hrZusatzCheck()` |
| 账号状态 | `e.account.state`：none / invited / accepted / pending_link / active / disabled / expired / revoked / send_failed |
| 员工编号 | `e.employeeNo`，同一雇主下不重复，重聘沿用 |
| 合同版本 | 合同条件按“生效日期”存版本列表；`e.contract` 始终是今天有效的版本 |
| 员工端提交 | 草稿、冻结提交（`invite.submitted`）、店长核对、正式档案是四层；采纳严格按冻结内容。修改请求写 `e.employeePortal.updateRequest`，补件写 `e.request.*` |

### 各页面做了什么

- 员工档案、员工资料、新增员工、入职邀请、邀请详情、证件到期、合规设置：逐条对应差异清单第 1–7 节；逐条结论（已做 / 暂缺 / 保留默认并带“待老板确认”）在 Owner 的执行账本 `员工助手-执行账本/prototype-items/` 里。
- 邀请：邮件是固定的中德英三语通用信，不能编辑；7 天有效，每个员工每天最多重发一次，重发换新链接、旧链接失效；撤销标“已撤销”并写原因，审核通过后只能“取消入职”。
- 合同：上传合同和个人问卷两份 → 发送；员工两份都签回才算签回；逐份核对，只退回没通过的那份；发错可作废（写原因，旧件保留）重发；线下签署可直接上传两份扫描件一步归档。
- 离职：“谁提出”四种；最后工作日当天及以前仍在岗，次日起才是已离职；最早最后工作日只是参考值，不是法律意见；撤销离职必须写原因；离职交接清单四项；资料保存期按五类设置，到期只给老板待办，一期不真的删除。
- 试用期结束日 = 入职日 + 月数 − 1 天，有效结束日不超过入职日 + 6 个月；提前转正只有老板可操作，并记录转正日期。
- 税务师权限、待办类型清单：见上方“演示入口”。

### “待老板确认”

- 老板问卷里还没答复的事项，页面上按规则文档的默认做法画出，并带虚线黄色小标签“待老板确认”（鼠标移上去显示题号和默认做法）。
- 汇总表在 `#employee-合规设置` 页底部（数据来自 `viewpoint.js` 的 `HR_BOSS_CONFIRM`）。老板答复后：改默认做法、删掉对应标签。
